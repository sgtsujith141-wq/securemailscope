# Local deployment

SecureMailScope runs entirely on one machine. There is no server to provision,
no container, no message broker and no cloud dependency, and nothing in the
application makes an outbound network request.

## Requirements

- Python 3.12
- Node.js 20 or later (for the interface only; the CLI and API need neither)
- About 400 MB of disk for dependencies, plus whatever your captures need

## Install

```bash
git clone <the private repository>
cd securemailscope

python3.12 -m venv .venv
.venv/bin/pip install -e '.[dev,backend,ml,reporting-tests]'

cd frontend && npm install && cd ..
```

The extras are separable on purpose:

| Extra | Brings | Without it |
|---|---|---|
| *(base)* | scapy, pydantic | The forensic engine and CLI work |
| `backend` | FastAPI, SQLAlchemy, Jinja2, ReportLab | No API, no HTML or PDF reports |
| `ml` | scikit-learn, numpy | ML reports `MODEL_UNAVAILABLE`; everything else is unaffected |
| `reporting-tests` | pypdf, pypdfium2, httpx | The PDF-rendering and API tests skip |

## Start the backend

```bash
.venv/bin/python -m securemailscope.backend.server
```

It prints where its data lives and the token a client needs:

```
SecureMailScope API on http://127.0.0.1:8765
  data directory : /Users/you/.securemailscope
  private storage: /Users/you/.securemailscope/storage
  API token      : <a per-installation token>
```

Useful flags:

```bash
--port 8765                  # change the port
--data-dir /path/to/data     # database, storage and token elsewhere
--print-token                # print the token and exit
```

The server **refuses** to bind anything but a loopback interface. Its security
model assumes localhost, and pretending otherwise would be worse than the
refusal.

## Start the interface

```bash
cd frontend
SMS_API=http://127.0.0.1:8765 \
SMS_API_TOKEN="$(cd .. && .venv/bin/python -m securemailscope.backend.server --print-token)" \
npm run dev
```

Then open <http://127.0.0.1:5173>.

The Vite dev server proxies `/api` to the backend and attaches the token, so
the browser talks to one origin and the token never appears in committed
source. `npm run build` produces a static bundle in `frontend/dist`.

## Where things are stored

| Item | Location | Committed? |
|---|---|---|
| Uploaded captures | `~/.securemailscope/storage/captures/*.bin` | **Never** |
| Generated reports | `~/.securemailscope/storage/reports/` | **Never** |
| Database | `~/.securemailscope/securemailscope.sqlite3` | **Never** |
| API token | `~/.securemailscope/api-token` | **Never** |
| Model artifacts | `src/securemailscope/ml/artifacts/` | Yes — generated by this project, integrity-verified on load |

Everything in the first four rows is outside the repository by construction,
not by a `.gitignore` rule that could be bypassed. Capture files are named from
a server-generated token, are readable only by the owner where the platform
supports it, and are not served by any route.

## Retention and deletion

Captures are kept until deleted. Deletion is an explicit action — there is no
automatic expiry — and it removes the stored bytes while **keeping** the
analysis results: deleting evidence does not retract what was already observed,
and silently discarding an investigation would lose work nobody asked to lose.

```bash
curl -H "x-securemailscope-token: $TOKEN" \
     -X DELETE http://127.0.0.1:8765/api/captures/<capture_id>
```

## The CLI still works on its own

Nothing in M7 changed it:

```bash
.venv/bin/python -m securemailscope analyze capture.pcap -o report.json
.venv/bin/python -m securemailscope analyze-batch a.pcap b.pcap -o investigation.json
```

## Handling a failed job

A job that fails records its reason and stays visible in the investigation. A
job interrupted by a restart is marked `FAILED` on the next start, with the
reason stated, rather than being left to look as though it were still running
or assumed to have completed. Re-running the analysis is the remedy; the
uploaded capture is still in storage.

## What this deployment never does

- Bind a non-loopback interface.
- Send telemetry, analytics or any outbound request.
- Contact a host observed in a capture.
- Download a model, a font or any other asset at runtime.
- Write capture data, reports or the database inside the repository.
